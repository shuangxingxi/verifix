# M13 项目状态分析方案（评审预演法）

- 制定时间：2026-11-15
- 目的：**不是"再读一遍代码"，而是用评委的提问方式反过来检验自己**
- 适用范围：初赛材料定稿前（2026-11-30）的全部自检
- 产出：`docs/devlog/m13-selfcheck-report.md` + `scripts/selfcheck.py`

---

## 0. 为什么需要一套方案

评审只会问三类问题，且只问这三类：

| 评委的潜台词 | 对应检验维度 |
|---|---|
| "你这个数是真的吗？" | D2 能力真实性 + D3 证据完整性 |
| "边界在哪，什么做不到？" | D4 口径一致性（含"不可声称"清单） |
| "换个人能复现吗？" | D1 可复现性 |

所以分析方案的每一个检查项，都必须能映射回这三问之一。映射不上的检查项，删掉。

---

## 1. 判定标尺：四级可信度（先定义"完成"）

任何一条声称，必须落在下面某一级，并在材料里显式标注级别。**混级即失分。**

| 级别 | 定义 | 判据 | 材料里的写法 |
|---|---|---|---|
| **L4 可复现** | 任何人按命令跑，得到同一结果 | 命令 + 退出码 + 证据文件 + sha256 | "实测：`xxx`（证据 `VER-2026…`，sha256 `19ca05…`）" |
| **L3 环境相关** | 有真执行，但依赖特定环境（本机 WSL2 / 特定镜像） | 执行域声明 + 不得外推声明 | "在 WSL2 内核实测；CCE 节点需复测" |
| **L2 有桩** | 代码路径完整，但外部系统是录制桩 | 报告自述"录制桩" | "适配器已接，外部系统为桩，未接真凭据" |
| **L1 只有承诺** | 只有文档里的设计，无代码无证据 | 无 | 只能出现在"演进规划"，不得出现在"已完成" |

**当前基线分布（11-15）**：L4 约 9 项（M6/M7/M8/评测隔离/指标复算/690 用例/权限基线/覆盖率/前端构建）、L3 约 3 项、L2 约 4 项（CodeArts 三适配器、M1 检出）、L1 约 6 项（云上、24h、性能、PPT、视频、自举）。

## 2. 五个检验维度

### D1 可复现性：换台机器能不能跑起来

| 检查项 | 方法 | 通过标准 | 当前 |
|---|---|---|---|
| D1-1 干净环境安装 | 新建目录 `git archive` 导出 → 装依赖 | 无隐式环境变量依赖 | ❌ 依赖 `PYTHONUTF8=1` |
| D1-2 全量回归 | `python -m unittest discover -s backend/tests -p "test_*.py"` | 0 error 0 failure，默认环境 | ❌ 8 error + 1 failure |
| D1-3 空转闭环 | `python scripts/smoke_m0.py` | `chain_valid=True` | ✅ |
| D1-4 15 分钟路径 | 按 README §3 逐条敲 | 从零到第一条指标 ≤15 min | ⚠️ 未计时验证 |
| D1-5 前端构建 | `cd frontend && npm ci && npm run build` | 无 error，dist 产出 | ✅（11-14 19:29） |
| D1-6 沙箱复现 | `build_sandbox_images.py` + `run_sandbox_verify.py` | 退出码 0，证据落盘 | ✅（需 WSL2+Docker） |

**判定规则**：D1 任一 ❌，整个项目的"可复现"叙事不成立，材料里所有 L4 都要降级说明。

---

### D2 能力真实性：每个数字是怎么来的

对每个对外声称的数字，填一行"来源追溯表"：

| 数字 | 声称 | 真实来源 | 等级 | 可否对外 |
|---|---|---|---|---|
| 检出 10/10 | M1 | 录制桩派生（m6 §7.4 自认） | L2 | 只能说"靶场真扫 15/15" |
| 造红 10/10 | M2 | 真执行（local-dev 后端） | L3 | 可，需注明后端 |
| 一次修好 10/10 | M3 | 模板命中（2 行补丁） | L3 | 可，需注明"模板覆盖 3 类" |
| 沙箱 10 类 PASS | M6 | 容器内真执行 | L4 | 可 |
| 靶场 15/15 | M7 | 容器内真扫 | L4 | 可 |
| 隔离 5 探针拒绝 | M8 | 容器域真执行 | L4 | 可 |
| 690 用例 | m12 | 依赖 PYTHONUTF8 | L3 | 修复后升 L4 |
| 行覆盖 54.5% | m11 | 标准库 trace | L4 | 可，须同时给判定函数口径 |
| M9 24h | m4 | 受控时钟加速模拟 | L1 | **不可**，只能写"未验证" |
| CodeArts 三集成 | I1–I4 | 录制桩 | L2 | 只能写"接口就绪，待接真凭据" |

**判定规则**：任何 L1/L2 的数字出现在 PPT 首页或模板1"已实现"栏，是硬伤。

---

### D3 证据完整性：说得出口的，点得开

| 检查项 | 方法 | 通过标准 |
|---|---|---|
| D3-1 声称→证据映射 | m12 §4"可声称"逐条找 `.evidence/` 文件 | 每条至少 1 个证据，且 sha256 可校验 |
| D3-2 孤儿证据 | 扫 `.evidence/` 152 个文件，反查被哪些报告引用 | 孤儿率 ≤10% |
| D3-3 证据不可篡改 | 校验 sha256 与文件实际值 | 100% 一致 |
| D3-4 报告只读性 | 已归档报告是否被后续修改 | 历史报告 sha256 未变（m6 已示范） |

**判定规则**：m12 的"可声称"清单是本项目的对外边界，D3 就是验证这份边界没有虚报。

---

### D4 口径一致性：同一个数，四个地方是不是一个值

固定四个载体：`README.md` / `docs/devlog/m12` / `deliverables/CodeArts方案.md` / 未来 PPT。

| 冲突点 | 现状 | 处置 |
|---|---|---|
| 覆盖率 54.5% vs 目标 80% | m11 如实写未达标；m12 §6 建议改口径 | **禁止只改口径**；须双列（全模块 / 判定函数） |
| M9 24h | m4 自认模拟、m12 列"不可声称"、README 需核 | 统一为"未验证" |
| 缺陷类 12 vs 3 | 边界说明书已改"MVP 3 类" | 需回填到 README §1 |
| 样本量 n=2~3 | 指标报告分母小 | PPT 不单列百分比，改列"n=3，方向性结论" |
| 支出口径 L0 | "自动合并" vs "仅并预发分支" | 统一为"合并到 `release/auto`，永不并 main" |

**判定规则**：D4 不做"选一个数"，只做"所有地方用同一个数，并附样本量"。

## 3. 执行方式：一半自动，一半人工

### 自动化部分（`scripts/selfcheck.py`，一次跑完 D1 + D3 + D4）

```python
# 伪代码，按此实现
checks = []
# D1-2 全量回归（父进程不设 PYTHONUTF8，模拟评委环境）
r = run([sys.executable, "-m", "unittest", "discover", "-s", "backend/tests", "-p", "test_*.py"])
checks.append(("D1-2", r.returncode == 0, parse_counts(r.stdout)))
# D1-3 空转
r = run([sys.executable, "scripts/smoke_m0.py"])
checks.append(("D1-3", "chain_valid=True" in r.stdout, ""))
# D3-2 孤儿证据：收集报告里出现的证据 id，与 .evidence 实际文件做差集
# D3-3 sha256 校验：报告里的 sha256 与文件实际摘要比对
# D4 口径：正则抓 README / m12 / CodeArts方案 里的 "54.5"、"24h"、"12 类"、"3 类"
# 输出 docs/devlog/m13-selfcheck-report.md + selfcheck.json
```

退出码：`0=全通过 / 2=有警告 / 3=有阻塞`（与现有 `run_sandbox_verify.py` 语义一致）。

### 人工部分（D2、D5）

- D2：把第 2 节的"来源追溯表"填满，逐行判级——**这一步不能自动化，因为要判断"桩"和"真"的区别**
- D5：拿模板1 原文对照，缺一项记一项

## 5. 方案自身的验收

跑完这套，必须能一句话回答三个问题：

1. **最弱的一环是什么？** —— 应该是"云上零部署 + CodeArts 无真凭据"，两者都是 L1/L2
2. **评委会先问哪三个？** —— 大概是：M9 的 24 小时怎么来的、CodeArts 到底用没用、换个漏洞还能不能修
3. **15 天够不够？** —— 够，但顺序不能错：**先 Git 化 → 再 CodeArts 真链路 → 再云上 → 最后材料**

做不到这三答，方案就是没跑通，回去改检查项。

## 7. 一句话

> 分析方案的价值不在"知道进度"，而在**把每一条对外声称都逼到证据上**：说不出证据的，降级；降不了级的，删掉。删掉之后还站得住的部分，就是能拿去答辩的部分。
