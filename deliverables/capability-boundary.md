# 能力边界说明书

**安全审计 · 测试 · 修复 · 自运行全流程 Agent** ｜ 第十一届华为 ICT 大赛 创新赛 · 赛题 2
版本 v1.0 ｜ 2026-11-10

---

## 一、一句话界定

> 本系统是一个**可验证的自动修复引擎**：它以「仓库 + 可执行环境」为输入，以「带证据的补丁 + 门禁结论」为输出。安全只是它的第一个插件。

它不是漏洞扫描器（扫描器只报不修），也不是代码生成器（生成器改了但无法证明改对）。它与二者的分界线是一条可执行的测试：**补丁必须让一条原本变红的测试变绿，且不弄红任何其他测试。**

---

## 二、边界法则

```
可测试性  =  可自动化的边界

能判定对错   →  Detect → Reproduce → Patch → Verify → Gate 全闭环
只能人判断   →  止步 L2（仅报告 + 建议 diff）
判不了对错   →  不纳入覆盖范围
```

这条法则决定了系统的能力上限不由模型强弱决定，而由「问题能否被一条测试表述」决定。这也是本项目所有指标可被第三方复跑验证的根本原因。

---

## 三、四级能力定义

| 级别 | 定义 | 人的介入 | 典型形态 |
|---|---|---|---|
| **A** | 检测 → 复现 → 修复 → 验证 → 门禁全自动 | 无（或仅事后抽检） | 依赖 CVE 升级、注入类修复、配置基线对齐 |
| **B** | 自动产出候选补丁与证据，合并权在人 | 一次代码评审 | 弱加密迁移、SSRF 白名单、镜像重建 |
| **C** | 自动检测、定级、给修复建议，不改代码 | 全人工处置 | 竞态、契约级鉴权缺陷 |
| **✗** | 资产承载该缺陷，但明确不覆盖 | — | 业务逻辑漏洞、0day、内存安全类 |

## 四、覆盖规模

```
能力地图：资产 6 类 × 缺陷 12 类 × 触发 5 种 × 处置 4 级
闭环阶段 5 段（Detect / Triage / Reproduce / Patch / Verify+Gate）
主矩阵 60 格：A 45 格（75%）· B 9 格（15%）· C 6 格（10%）
本轮交付：Python 单语言 × 缺陷 3 类（C01 · C02/C03 · C05）
```

- **资产**：应用代码 · 第三方依赖 · IaC 与云配置 · 容器镜像 · 密钥与凭据 · API 契约
- **缺陷**：依赖 CVE、SQL 注入、命令注入、路径穿越、硬编码凭据、不安全反序列化、弱加密、日志泄露、SSRF、配置基线、不安全随机数、竞态
- **本轮交付（MVP）**：依赖 CVE（C01）、注入（C02 SQL / C03 命令）、硬编码凭据（C05）。其余 8 类为演进边界（v2–v3），引擎已预留检测器接口，本轮不做验证。
- **触发**：定时扫描 · PR/push 门禁 · CVE 订阅 · 运行时告警 · 人工提交
- **处置**：L0 自动合并 · L1 开 PR 待人审 · L2 仅报告 · L3 拒绝处理

## 五、明确不做，以及为什么

| 不覆盖 | 理由（一句话） |
|---|---|
| 业务逻辑漏洞（越权、价格篡改、流程绕过） | 需要业务语义，无法自动生成「正确的业务预期」作为断言 |
| 0day / 未知漏洞 | 无规则、无样本、无历史修复可比对，闭环缺第一环 |
| 架构级缺陷（信任边界设计错误） | 不是几行代码能解决的，属设计决策，须人做 |
| 内存安全类（C/C++ UAF、缓冲区溢出） | 需 sanitizer + fuzzing 长跑，属独立技术栈与工期 |
| 供应链投毒（恶意依赖包） | 需包信誉数据与行为沙箱，超出本引擎证据模型 |
| 密码协议实现正确性 | 需形式化验证，测试覆盖不到 |

**说明**：主动声明不做什么，是为了让「做什么」可被信任。边界之外的请求一律降级为 L2 报告并转人工，不产生任何自动写入。

## 六、降级与熔断（安全底座）

- **最小改动约束**：单次补丁 ≤ 30 行、≤ 3 个文件；超出即降 L2，不自动提交。
- **三重门禁**：①新增/变更测试由「红→绿」验证；②全量回归零失败；③复扫告警数不增加。任一不满足即回滚。
- **分级治理**：低危 + 有测试覆盖 + 改动 ≤ 3 行 → L0；中危或改动较大 → L1；高危且方案不确定 → L2；判不了对错 → L3。
- **熔断**：同一缺陷类型连续 3 次修复失败，自动停用该类处置并告警；失败指纹入黑名单，不重复尝试。
- **成本闸门**：单 issue ≤ 5 次模型调用、≤ 0.5 元；超限转人工。
- **全链路留痕**：who / what / why / evidence 四要素落库，任一自动动作可追溯、可撤销。

## 八、结论

> 能力地图覆盖 **6 类资产 × 12 类缺陷 × 5 种触发 × 4 级处置**；**本轮交付 Python × 3 类**（依赖 CVE / 注入 / 硬编码凭据），三类恰好对应「版本可判定 / 数据流可追踪 / 字面量可匹配」三种验证范式。在「可用测试判定对错」的边界内实现无人干预闭环；边界之外（业务逻辑、0day、架构设计、内存安全、其余 9 类缺陷）明确降级为人工处置或列入演进，并以分级治理、三重门禁与自动回滚保证任何自动动作都可撤销。

边界清晰不是能力不足的证明，而是工程可信的前提——**一个敢说清自己做不到什么的自动化系统，才敢让它自己跑。**
