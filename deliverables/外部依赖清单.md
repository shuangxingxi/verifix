# 外部依赖与接入顺序清单

> 用途：告诉交付负责人"还缺什么、谁来给、拿到后先做什么"。
> 原则：**未提供的外部输入一律登记为 BLOCKED，不用本机模拟替代。**

## 1. 依赖清单

| 编号 | 依赖项 | provided_by | 解除哪些交付项 | 到位后第一动作 | 验收方式 |
|---|---|---|---|---|---|
| EXT-01 | 华为云 AK/SK（或可用 ECS/CCE 配额） | 用户 | `DLV-B03` 云上部署 | 先跑最小探活（单实例 8443 health），再按 `deploy/cce` 清单扩容 | `curl https://<host>:8443/health` 返回 200；附部署日志 |
| EXT-02 | CodeArts 仓库地址与账号 | 用户 | `DLV-A02` 真实远端与 PR | 建远端 → 推送历史 → 按五步前缀补 ①②③ 提交 → 开真实 PR | `git remote -v` 有值；PR 有编号与合并记录 |
| EXT-03 | 云上演示入口域名/公网 IP | 用户 | `DLV-C02` 公网演示 | 部署完成后配置 nginx 与证书，开放 8443 | 外部网络访问演示页可用 |
| EXT-04 | 录屏环境与讲解人 | 用户 | `DLV-D08` 演示视频 | 按 `deliverables/演示脚本.md` 预演一遍，再正式录制 | 视频文件存在且时长与脚本一致 |
| EXT-05 | PPT 成片确认 | 用户 | `DLV-D07` 演示文稿 | 用 `deliverables/评审应答卡.md` 校对口径后定稿 | 文件存在，页级大纲与应答卡一致 |
| EXT-06 | 独立评审人 | 用户 | `DLV-E02` 第三方签署 | 抽样复核 AC-08 的 10 项，签署时间与范围 | 签署记录齐全；同一人兼任须显式标注 |
| EXT-07 | 参赛队名 | 用户 | `DLV-D01` 材料完整性 | 填入 `deliverables/CodeArts方案.md` 封面表"队名待补" | 全文无占位符 |

## 2. 接入顺序（严格串行，不可跳步）

1. **EXT-07 队名** → 关闭 `DLV-D01` 的最后一个占位符（成本最低，先做）。
2. **EXT-02 CodeArts 账号** → 建立真实远端；这是五步留痕 ④⑤ 的前置。
3. **EXT-01 云凭据** → 最小探活 → 全量部署 → `DLV-B03`。
4. **EXT-03 演示入口** → 依赖第 3 步完成。
5. **EXT-04/05 素材** → 在系统可演示后再录制，避免录到未就绪画面。
6. **EXT-06 独立评审** → 最后做，基于已定稿的材料与证据。

## 3. 拿到凭据后的边界（重要）

即使凭据到位，以下结论**仍需重新取证，不能直接改判**：

- 云上部署：必须有真实部署日志、8443 探活记录、回滚演练记录，缺一不可。
- 五步留痕：③④⑤ 必须产生**真实提交**，前缀与规范一致；不得用 `--amend` 或时间回填凑。
- 覆盖率：若要在云上跑覆盖率，需先解决 `coverage` 工具安装与分支覆盖口径，否则仍是行覆盖。

## 4. 当前没有凭据时的结论

`DLV-A02`、`DLV-B03`、`DLV-C02` 固定为 `BLOCKED`，`reason_code = NO_CREDENTIAL | NO_ACCOUNT`，`fallback = NONE`。
`DLV-D07`、`DLV-D08`、`DLV-E02` 固定为 `BLOCKED` 或 `NOT_STARTED`（草案不算成片）。
**不得因为"其余都做完了"就宣布交付包 PASS**——DoD 按最差项收敛。
