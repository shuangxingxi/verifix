## 3. 高危问题应答

**Q1：为什么 AC-01 是 fail？**
A：AC-01 要求仓库只有一次提交且无父提交。实际为支撑 AC-13 检索缺陷修正与证据入库，产生了后续提交，客观变为 fail。我们没有改判 pass，而是定义了替代口径 AC-01R（基线提交 `ecfcad3` 自身仍满足单提交与无父提交），并在报告里并列写明。**回退会让 AC-13 修正丢失，所以选择如实记录。**

**Q2：PERF-02 到底修没修？**
A：没有改断言、没有调阈值。实测发现用例测的是 `capture` 端到端耗时（含脱敏、序列化、摘要、落盘），而需求条款约束的是"读操作对主流程写入的阻塞"；另用写阻塞协议直测，`delta_p95 = −0.0014ms`。因此裁定为阈值口径问题，并登记 `capture_budget_ms` 无消费点的实现缺口（IF-01）。

**Q3：为什么覆盖率只有 54.5%？**
A：本机 `coverage` 工具因镜像不可达装不上，只能按行覆盖统计；且 dataclass/Protocol 等声明行会系统性拉低数值。G-11 的 80% 目标未达，我们如实标注，没有改口径凑数。

**Q4：没有云上环境怎么证明可部署？**
A：诚实回答：**云上未实测**。本机能证明的是：编排结构合法、镜像构建定义齐全、本机服务链路可运行。云上部署所需凭据与账号未提供，我们把它登记为 `BLOCKED`，而不是用本地模拟替代。

**Q5：自检为什么还有 7 条阻塞？**
A：其中 2 条是 ④⑤ 步骤未执行，5 条是五步提交前缀缺失（因基线提交不计入留痕）。这两类都需要真实步骤提交与外部环境，属于明示阻塞，不是漏做。

**Q6：指标为什么是 UNDETERMINED？**
A：M9 连续自运行缺少达标证据：复算口径为 `EVIDENCE_MISSING`；我们另做了 2 小时真实短跑（`origin=runtime`、121 条采样、中断 0），实测 7200 秒，判定 `INSUFFICIENT_DURATION`。按规则不得用夹具采样转正，也不得把不足 24h 的短跑写成达标。M4/M5/M6 本身达标，但报告结论必须按最差项收敛。

**Q7：8 个编码 error 是怎么回事？**
A：经全仓追溯，那是 `m13-analysis-plan.md` 里的计划值，从未有清单与归档输出；后续四次自检均为 `errors=0`。所以不列入待修项，避免虚构工作量。

**Q8：这些数据能现场复算吗？**
A：可以。复算命令与证据路径写在 `deliverables/指标口径表.md` 与 `deliverables/演示脚本.md`，全程离线。

## 4. 一分钟电梯陈述

VeriFix 把"告警可达性 → 复现造红 → 最小补丁 → 六条审计 → 三闸 → 灰度"做成可回放状态机，用评测集持续校验"检出可信、补丁一次修好、指标可复算"。本机已演示十个入口与看板六要素，指标 M4/M5/M6 达标，评测集做了输入/答案物理隔离。云上与真实 CodeArts 链路因无凭据未实测，我们按阻塞如实登记，不伪造结果。
